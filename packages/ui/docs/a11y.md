# Keyboard and screen-reader contract

What each component promises. "Auto" = asserted by a test in `src/components/components.test.tsx` (axe + Testing Library).
"Manual" = expected platform behaviour, **[UNVERIFIED]** with a real screen reader until recorded here.

| Component | Keyboard | Screen reader | Verification |
|---|---|---|---|
| Button | Tab focuses; Enter and Space activate. `loading` keeps focus and ignores activation | Role `button`; `aria-busy` while loading; defaults to `type="button"` | Auto: keyboard, busy state, axe |
| Input | Standard text input keys | Label via `<label for>`; hint and error joined in accessible description; `aria-invalid` only when an error exists | Auto: description string, invalid state, axe |
| Select | Native: arrows, type-ahead, Enter/Esc per platform | Role `combobox` with label name; hint and error described | Auto: selection, name, axe. Manual: VoiceOver/NVDA announcements |
| Dialog | Native `showModal`: focus moves in, Tab trapped, Esc closes, focus returns to opener | Role `dialog`, named by its title (`aria-labelledby`); background inert | Auto: role, name, open/close, close event, axe. Focus trap and Esc are browser features (jsdom can't prove them): Manual / Playwright (M1 visual suite) |
| Toast | Close button reachable by Tab; errors never auto-dismiss (WCAG 2.2.1) | Info in `role="status"` (polite) region, errors in `role="alert"`; regions are always mounted | Auto: regions, dismiss, timing, axe. Manual: announcement timing across SRs |
| ThemeProvider | n/a | n/a. Respects `prefers-color-scheme` when set to `system` | Auto: data-theme, persistence |

## Known limits
- Colour contrast is not checked under jsdom. Storybook's a11y addon runs axe in a real browser (`parameters.a11y.test = "error"`), and tokens were chosen for AA contrast. **[UNVERIFIED]**: no contrast numbers recorded yet; add a token contrast test in M1 follow-up.
- Automated axe finds only a subset of WCAG failures.
